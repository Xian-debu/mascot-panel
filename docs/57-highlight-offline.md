# 57 代码块高亮与离线待发队列（M42）

阶段 C 的最后两项：看得清（代码块高亮）、丢不了（发不出去的消息排队重发）。

## C5 代码块语法高亮

### 为什么自己写

面板 HTML 是内联单文件（KaTeX 已经占了 604K），再塞一个 highlight.js（~200K + 主题）
不划算，而且我们只需要"模型实际会吐的那十几种语言"。所以写了个 ~200 行的分词器
`web/js/highlight.js`，输出 `<span class="hl-xx">`，全程 `textContent`，不拼 innerHTML。

### 覆盖范围

- 语言：python / javascript / typescript / json / bash / sql / c / cpp / rust / go / java(+cs/kt/swift/scala) /
  yaml·toml·ini / css·scss / html·xml。未知语言按纯文本渲染（不报错、不加标签）。
- 注释风格：`#`（py/bash/yml）、`//` 与 `/* */`（C 系）、`--`（SQL）、`/* */`（CSS）、`<!-- -->`（HTML）。
- 类别：关键字、字符串、数字、注释、函数名（标识符后紧跟 `(`）、运算符/标点。
- 语言名标签：围栏写 ```python 时，代码块左上角显示灰色的 `python`（`pre.has-lang` 加 16px 上内边距）。

### 接入点

`markdown.js` 的 `codeEl(code, lang)`：先试 `M.highlightInto(box, code, lang)`，返回 false（不认识这门语言）
才退回 `box.textContent = code`。围栏解析处把语言名 `m[2]` 透传进来（以前只取了代码体，语言名被丢了）。

模块顺序：`highlight.js` 排在 `markdown.js` 之前（`runtime.py` 的 `JS_MODULES`）。

### 配色

Tokyo Night 系，深底上不刺眼：关键字 `#7aa2f7`、字符串 `#9ece6a`、数字 `#ffb86c`、注释 `#6b7f8f`（斜体）、
函数 `#7dcfff`、运算符 `#a9b1d6`。

### 验收（真机，开发副本）

python / bash / sql / javascript / json 各建一个测试会话截图确认：关键字、字符串、注释、数字、函数名都上色，
缩进与长行横向滚动不受影响，语言标签在左上角不压住代码。

## C6 离线待发队列

### 行为

发送失败（401、断网、超时）时，这条用户消息不再只是"记一个 _failed_text 等用户点重试"，而是：

1. 消息本身留在会话里（用户看得到自己说了什么）；
2. 文本 + 消息 id 写入 `<状态目录>/outbox.json`（原子写，上限 50 条，同文本去重）；
3. 横幅显示「N 条已排队，恢复后自动发」，仍可点「重试」立刻手动重发；
4. 后端健康探测（每 5s）发现恢复、且面板闲着 → 自动重发整个队列：逐条按原顺序发，
   发之前先从会话里摘掉那条原消息（否则会出现两条一样的）。

### 关键设计

- **持久化**：进程被杀也不丢——`load_outbox()` 在启动时读，第一次健康探测就自动冲刷。
- **防抖**：发失败后 `_outbox_next = now + 30s`，避免后端"健康但聊天 401"时每 5s 撞一次；
  手动点「重试」不受这个限制。
- **顺序**：队列按失败顺序入 `_send_queue`，串行发送线程保证一条一条来。
- **不丢也不重复**：重发前删原消息靠 `msg_id`，id 是 `local-<sid>-<time_ns>`，合并/拖动都不会撞。

### 验收（真机，开发副本）

1. 坏 key 启动 → 连发两条 → `outbox.json` 里两条、横幅「2 条已排队」；
2. 打开设置页用剪贴板粘回真实 key 保存 → 5s 内状态回绿、队列自动冲刷、收到两条真实回复、
   `outbox.json` 被删除、会话里正好 2 用户 + 2 回复（无重复）；
3. 重启场景：坏 key 发一条 → 杀进程 → 正常 key 重启 → 首次探测自动重发，会话里 6 条（3 用户 + 3 回复）。
